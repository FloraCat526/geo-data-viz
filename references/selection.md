# 从数据到地图效果的匹配规则

本文件指导 Agent 作出并解释选择；`profile_geo.py` 提供数据证据，不是自动理解业务或自动判定所有 SDK 能力的分类器。不要仅根据文件后缀、点数或出现一个数值列就定图。recommendations 不排序，eligible 是结构可用而非业务最优；needs-transform 的条件未落实前不可当成现成效果，blocked 不能直接生成。数据转换见 [配方](transforms.md)。

## 1. 先形成数据事实

地图选择独立于效果选择：明确图商 → 使用该服务和本任务已授权配置；未指定 → 沿用唯一适用的授权配置；两者都没有 → MapLibre + OpenFreeMap，无需询问 Key。先按问题进入**可视化组件**（分布、密度、连接与区域差异）、**场景叙事组件**（行程或章节时间轴）、**地球模式组件**（全球球面视角）之一，再按下面的数据条件选择效果并映射到该引擎能力；不能为了套用某个效果模板而换掉用户指定的图商。

从 profile、必要样例及用户目标提取以下信息。脚本未提供的统计按任务补算，不把未知写成已检测：

| 维度 | 要确认的事实 | 对选型的影响 |
|---|---|---|
| 几何 | 点、路径、区域、多部件；OD 两端；只有地址/行政编码 | 决定可画哪些形状、是否还缺坐标/边界 |
| 记录粒度 | 一行一个门店、订单、车辆采样、区域月份，还是已聚合网格 | 避免重复计数、重复汇总、跨实体连线 |
| 指标 | 数量、金额、强度、比例、等级、正负变化；单位与分母 | 决定面积、连续/发散颜色、求和或加权比率 |
| 时间 | 时间戳/区间、时区、实体内顺序、采样间隔与缺口 | 时间筛选、变化对比和轨迹播放不是一回事 |
| 空间 | CRS 来源、覆盖范围、同位置不同实体、视口中的重叠情况 | 坐标转换、聚合、投影/日期线与拾取 |
| 规模 | 记录数、顶点数、文件字节、更新频率、目标设备 | 原生批量层、WebGL、汇总或切片；通过实测决定 |

## 2. 分析目标 → 字段 → 聚合 → 组件

这张表是选型主入口。先匹配用户要回答的问题，再检查必需字段；不要从组件名称倒推业务目标。字段名为角色，不要求源文件使用相同名称。所有空间字段都需确认 CRS；转换后才传给目标组件。

下表的所有平面效果都对应[可视化组件统一清单](visualizations.md)，由 `build_visual_html.py` 或 `createViz` 按 effect 直接选择。指定其他图商时保留分析与聚合口径，转到该图商能力文档核查可用 API，不能照搬 MapLibre 类名。

| 分析目标 / 常见问题 | 必需字段与记录粒度 | 聚合方式 | 具体组件 / 参数 | 不适用条件与替代 |
|---|---|---|---|---|
| 地点在哪里：门店、设施分布 | Point 或经纬度；一行一个实体，名称/ID 可用于详情 | 不聚合；同位置不同实体保留 | `points` 散点组件 | 只剩地址时请用户补充坐标或已定位文件；本 Skill 不调用地理编码服务，不能凭名称猜点 |
| 不同类别如何分布 | 位置＋类别；每实体类别含义明确 | 不聚合；固定全量类别色表 | `category-points` 分类点组件 | 类别很多时支持筛选，不用连续色阶暗示类别高低 |
| 哪个地点规模更大：销量、容量、资产 | 位置＋规模指标＋单位；同一统计时间与粒度 | 单体值；重复业务明细先按实体求和，快照不可跨期累加 | `bubble` 气泡组件，面积编码；可选 `bubbleEntrance: true` | ID/年份不是规模；长尾过强时配合详情；缺失不作零 |
| 温度、等级、风险率在空间上有何差异 | 位置＋数值＋单位/阈值；比率有定义 | 单点值，不随意求和 | `point-color` 数值着色点组件 | 温度不是可加贡献；若要推断未观测区域需独立空间插值方法 |
| 哪里亏损、增长或下降 | 位置＋有符号指标，零点有含义 | 同粒度净值；确认可加性 | `point-color` 发散色；需面积时 `bubble, sizeMode: absolute, colorBy: value` | 不能丢符号后解释为总量；不送入仅接受非负数的热力/蜂窝指标 |
| 地点太密，但仍需逐条浏览 | Point、实体 ID；确认目标视野有重叠 | SDK 屏幕聚合，随缩放改变成员 | `cluster` 点聚合组件 | 不是固定空间单元统计，不用于比较各行政区数量；需固定汇总用蜂窝/区域设色 |
| 事件集中在哪里 | Point；确认一行一个事件或实体，确定时间窗口 | 每点权重 1 | `heatmap, weight: count` 热力组件 | 热区不是风险率或客流预测；精确比较格内数量用蜂窝 |
| 哪些位置贡献总量更多 | Point＋非负可加指标，如订单金额 | 每点按指标加权；先处理重复明细 | `heatmap, weight: value` 热力组件 | 温度、比率不可直接作求和贡献；需读取准确数值用蜂窝 sum |
| 按相同空间尺度比较数量 | Point；一行含义明确 | 固定原点/边长，格内 count | `hexagon`，`aggregation: count`、`cellSize`、`mode: flat` | cellSize 是米制边长；限本地近似投影区域，非全球等面积网格；细节见组件限制 |
| 各蜂窝贡献多少总量 | Point＋非负可加指标 | 格内 sum，缺失另计 | `hexagon`，`aggregation: sum`、`valueField`、`cellSize` | 已有区域/网格统计不能再当点记录计数；比例不可求和 |
| 各蜂窝平均观测水平 | Point＋非负观测值；等权样本与时间窗合理 | 格内有效样本 mean；保留样本数与缺失数 | `hexagon`，`aggregation: mean`、`valueField` | 本组件不接受负温度、不实现加权均值；此时先外部聚合成面，再用 `fill` |
| 用三维强调空间集聚或贡献 | 上述蜂窝输入，或已有统计面＋非负指标 | 与二维方案完全相同；再映射高度 | `hexagon` 的 3D 模式；已有面用 `extrusion` | 高度为值×比例，不是建筑高度；遮挡妨碍比较时以平面为主、3D 为备选 |
| 突出少量告警或关注事件 | Point＋已确定的事件筛选/等级依据 | 通常不聚合，先筛选待强调事件 | `pulse` 呼吸点组件 | 呼吸是视觉强调，不是新增分析，不代表影响半径或实时波传播 |
| 物流、迁徙、机场之间有什么连接 | 起点＋终点坐标、唯一连接 ID；可选类别/流量 | 明细按 OD 与时间窗口合并；按业务决定连接去重或流量求和 | `flight` 飞线组件 | 只有单端地点不可造 OD；弧线非真实路线。当前组件不自动按流量映射线宽，不宣称有此编码 |
| 全球跨洲连接如何分布 | 起点＋终点 WGS84 坐标、唯一 ID、可选类别；OD 记录 | 按连接与时间窗去重；有流量才可另行编码流量 | 地球 `GlobeFlightLayer`；`build_globe_html.py --effect flight` | 全球视角才有价值；球面弧线不是实际航迹，只有一端坐标不能生成 |
| 已有道路、管线、轨迹形状在哪里 | LineString / MultiLineString；原始顶点顺序与分段 | 保留线形，不连接无关段 | `line` 组件 | OD 两点不是已知实际道路；未知路径不通过平滑补成“真实路线” |
| 多日旅游行程怎样总览与逐日查看 | WGS84 站点、稳定 ID、所属日期或天序、日内顺序；可选时间/说明；真实路线另需 LineString | 不聚合，按天组织并保持原顺序；路径几何按可靠关联绑定日期 | `prepare_itinerary.py` → `TravelItineraryLayer` / `build_itinerary_html.py`；[输入与交互](travel-itinerary.md) | 只有站点时仅画虚线示意连接，不推断道路、路程或用时；只有地址不能生成点 |
| 历史故事、出征或事件如何按章节在地图上展开 | WGS84 事件点、稳定 ID、明确顺序；日期和叙述可选；真实路段另需 LineString | 不聚合，保持叙事顺序；动画按章节推进 | `prepare_story.py` → `StoryTimelineLayer` / `build_story_html.py`；[故事时间轴](story-timeline.md) | 缺路径只画虚线示意；章节播放不等于真实时刻、真实路线或行进速度 |
| 地理故事怎样通过镜头、地点和路线进行讲解 | WGS84 地点/已提供路线＋章节文本；可选图片、已有旁白；镜头帧段独立于业务时间 | 不聚合；按章节组织内容与相机起止状态 | `SceneNarrativeViz` / `build_scene_html.py`；明确要视频时 `build_scene_video.py`；[场景镜头](scene-narrative.md) | 不调用 Directions；镜头轨迹不能当作业务轨迹，只有地点时路线标为示意 |
| 在山地或三维城市中跟随用户路线飞越 | 已提供路线与地点；另有可用 DEM/影像/3D Tiles 和授权配置 | 保留用户几何，叙事高度单独配置 | 地形底图＋`SceneNarrativeViz`；三维资产用 Cesium 场景目标；[底图](basemaps.md)、[Cesium](capabilities/cesium.md) | 缺地形或三维资源不伪造；影像纹理不等于真实地形，指标拉伸不等于地面高程 |
| 基于一张已有地图图片讲解地点与路线 | 用户提供图片＋WGS84 `geoBounds`＋地点/路线，或不定位的纯图解 | 不聚合；在明确地理范围内映射位置 | `SceneNarrativeViz` 的 `static` 目标；[静态场景](scene-narrative.md) | 本组件需地图图片覆盖范围；一般海报/非地理插画不适用，不把任意图片自动当地图 |
| 按真实时间查看车辆/人员移动 | 实体 ID＋坐标＋时间戳，采样顺序明确 | 按实体、时间排序，处理缺口并分段 | **需任务实现**：时间戳轨迹播放；详见转换配方与所选图商能力 | 普通线只呈现路径形状，不是已封装的真实轨迹回放组件 |
| 比较行政区指标或比例 | Polygon / MultiPolygon＋稳定地域编码＋指标；边界年份匹配 | 按区域关联；比率上卷用 sum(分子)/sum(分母) | `fill, colorBy: value` 组件 | 只有名称不造边界；不得平均百分比代替加权比率；统计缺失与零区分 |
| 展示已有区域的类别或范围 | Polygon / MultiPolygon；按类别着色时还需明确类别字段 | 不聚合，不编造统计值 | `fill, colorBy: category/constant` 组件 | 颜色不表示数值大小；没有面几何时不能凭名称补造边界 |
| 全球国家/地区指标如何分布 | WGS84 国家/地区 Polygon＋明确年份、区域关联键、数值及单位 | 按稳定编码关联边界与指标；缺失保留 null | 地球 `GlobeChoroplethLayer`；`build_globe_html.py --effect choropleth` | 总量不能解释成密度；单半球不利于准确排名，必要时配平面图/表格 |
| 全球事件强度在哪里较高 | WGS84 Point＋可比较的数值及单位；每行一个事件 | 明确时间窗；异常与重复事件先处理 | 地球 `GlobeSpikeLayer`；`build_globe_html.py --effect spikes` | 点密时遮挡明显；视觉柱高不是物理高度或影响范围 |
| 展示建筑高度或区域指标柱 | 面轮廓＋非负高度/指标＋单位 | 物理高度直接使用；指标高度明确缩放比例 | `extrusion, heightScale, unit`，配二维 `fill` | 经纬度点不是建筑 footprint；不能把人口柱称作真实楼高 |
| 展示雷达站扫描或风场/栅格 | 扫描须已知站点坐标；真实覆盖须另有范围依据；风场须向量，栅格须专用地理元数据 | 扫描逐站点绘制；半径为视觉参数，只有来源支持时才标为实测范围 | `radar` 雷达组件；风场/GeoTIFF **需专用解析与渲染** | 不把示意扇区称实测覆盖，不把普通点热力当作风场或遥感栅格 |

### 2.1 多个候选同时成立时怎样决定

- **比较单体大小**优先气泡；**看连续集中趋势**优先热力；**按固定空间尺度比较具体数值**优先蜂窝；**密集点逐条浏览**优先聚合。不要仅由点数选择。
- 用户想保留细小点并呈现发光位置纹理时，用散点的 `glow` / `blendMode:'additive'`；按缩放和点密度控制 `pointRadius/opacity/glowIntensity`，避免大面积饱和。加法亮度不是密度或业务指标；类别/数值比较优先普通混合。参数见[散点外观](class-reference.md#散点外观光晕与颜色叠加)。
- 已有业务区域且问题针对行政区，优先区域设色；没有业务边界但需要空间汇总，才采用统计网格。更换边长会改变统计结果，不把不同网格尺度当成同口径排名。
- 飞线回答“谁连接谁”，普通线展示已有路径形状；真实轨迹回放还需要实体和时间戳，不能由路径形状推断。
- 动画、入场与三维是表达选项，不额外赋予实时性或业务意义。默认用 `FlyLineViz`，不再提供另一种三维飞线组件。
- 矢量、影像和地形是底图选项，与 points/line/fill 等数据效果独立。统计比较默认保持清晰矢量底图；用户关注实际地貌或明确要求卫星时才读取[底图配置](basemaps.md)。视频是场景叙事的交付形式，仅在用户要求时启用 Remotion。
- 用户只说“帮我可视化”且无可确认指标时，先用位置/类别图并提供详情；可根据明确字段含义提出更合适的方案，不因缺少非关键偏好反复询问。
- 只推荐 1 个主方案、最多 2 个回答不同问题的备选；每个备选写明为什么有用，而不是罗列所有能画的效果。

### 2.2 从选型落到调用

1. 根据表中目标绑定源字段，确认记录粒度、时间窗、CRS 和指标单位。关键语义缺失才询问；可由数据或上下文判断则直接推进。
2. 写清统计口径并完成转换；验证记录数守恒、缺失处理、区域关联或 OD 配对。脚本候选只提供结构证据，不自动完成这些分析。
3. 平面可视化统一读取[组件清单与接口](visualizations.md)，按所选 effect 调用 `build_visual_html.py`。全球球面模式读取[地球组件](globe-effects.md)，用 `build_globe_html.py`；它是独立 Globe.GL 渲染器，不是 MapLibre 原生球面图层。
   旅游规划、故事时间轴或镜头叙事分别读取对应场景文档；镜头叙事用 `build_scene_html.py`，视频输出见[Remotion 入口](video-export.md)。底图类型单独记录，不能用 DEM 改写指标高度或统计值。
4. 不同表达仍有不同必要输入：点线面规范化数据读取 `properties.__viz`；蜂窝 `valueField` 指向原始数值属性；飞线要转换为唯一 ID、source、target 的 OD 数组。需要 MultiPoint 展开或字段提升时显式转换并保留来源 ID。
5. 若所选方法标为“仅示例/需任务实现”，不得承诺现成组件支持。改用已实现且能回答问题的方案，或基于已验证 API 完成本次实现后验收。

缺少必要输入时给出可执行的替代或仅询问关键缺项。用户点名的效果优先保留，但不能为了“炫酷”编造路径、统计值或业务阈值。

## 3. 将效果落到用户选定平台

先读 [能力索引](capabilities/index.md)，再读所选平台文件。对每个候选逐项判定：

1. **输入成立**：几何、粒度、指标、单位、时间是否满足。
2. **接入可行**：目标 SDK 版本、必需扩展、Key、map ID/安全配置、CRS 与网络是否具备。缺 Key 为待接入，不是厂商不支持。
3. **接口有证据**：公开文档或当前源码能定位类及所需参数；参考 Demo 名称不能当构造器。未确认扩展兼容性标待核实。
4. **交互和性能合适**：是否需要逐条拾取、暂停、筛选、高频更新、倾斜/遮挡；用户设备实际能否承载。
5. **跨平台口径可保持**：颜色、半径、聚合和时间语义一致；不同 native 聚合结果需要明确处理。

只有满足必要条件的候选才按“回答业务问题的程度 → 可读性与交互 → 运行成本 → 用户视觉偏好”排序。选择 1 个主方案和最多 2 个有实质区别的备选；不要用没有依据的精确分数、固定点数阈值或厂商优劣榜。

优先选择当前图商公开原生层/覆盖物或官方扩展。缺少目标效果时，按 [渲染归属](provider-rendering.md) 评估第三方库或独立 Canvas/WebGL 补充；记录实际缺口、补充来源和限制，保持所选图商与数据语义。数据分析、聚合和视觉映射可共用，渲染按目标图商逐层决策，不能因统一适配方便跳过已有原生能力。已明确可行的补充方案直接执行；全部路线仍不满足时再说明具体缺项。

## 4. 固定映射，再实现切换

- 在源 CRS 或明确的分析 CRS 下计算一次聚合与指标，渲染前再派生目标 CRS 坐标。境内外混合数据不可盲目批量加偏移。
- 气泡固定全量的面积域；颜色固定类别/阈值；筛选与切图不自动重标色。绘图大小区分半径/直径以及 px/meter。
- 严格比较网格时固定网格定义、大小、原点、CRS、成员和聚合函数，输出共同面数据。屏幕聚合仅用于浏览，可以随 zoom 改变成员，但不要称作稳定统计区域。
- 原生热力的核函数、带宽、归一化、累加和颜色曲线不同。同一批点、同一个最大值，并不能证明热力数值逐像素等价。要求严格比较时改用共同统计网格并由各家原生面层绘制，明确其为网格统计而非连续热力。
- 3D/动画增强可因平台不同而变化，但保留同一业务指标、筛选与详情；没有对应层时显示实际降级效果及原因。

## 5. 保留一份简短可检查的选型结果

## 选型校验案例

这些是可供人工复核的行为案例，不代表自动分类测试已实现：

| 请求 / 数据 | 应产生的判断 |
|---|---|
| 选择 Google，要展示订单集中区 | 核实每行订单计数；Google 旧 HeatmapLayer 已退出，可评估 deck.gl HeatmapLayer + GoogleMapsOverlay 或自绘热力补充；记录非原生来源和缺口，不复活旧 API。若用户明确要求仅原生，则采用准确命名的替代或说明无法满足 |
| 腾讯上显示传感器温度，有负值和小数 | 不截负、不取整、不把温度写进仅声明正整数 count 的 Heat；优先 Dot 颜色或预计算平均值区域 |
| 百度 4.0 + 炫酷飞线，只给起终点 | 定义 OD；核查 MapVGL 与当前 4.0 实例兼容，FlyLineLayer 的额外包；未核实前保留二维方向线备选 |
| Mapbox + 腾讯，对比六边形销售总额 | 共同生成格网并求和，再用面层；不能 Mapbox 求和、腾讯原生 Hexagon 默认点数 |
| 日期 + 门店点，但每店只有一条记录 | 可按日期筛选；不形成车辆轨迹，不因为有 time 列就选 Trips/Trail |
| 行政区转化率，只有百分比没有分母 | 可显示已有区域比率，不能跨区简单平均；若需上卷汇总先索取分子分母 |

## 新增组件的选型复核案例

| 数据 / 请求 | 应选与应排除 |
|---|---|
| 每单经纬度＋金额，要比较等尺度地区的销售贡献 | 蜂窝 sum(金额)，明确边长与时间窗；不用 count 冒充销售额，也不按订单数决定主图 |
| 站点温度含负数，要比较平均温度 | 点色阶或外部网格均值后 fill；本地 `HexagonViz` 仅非负指标，不直接调用 mean |
| 同样的门店数据，目标分别是单店规模和密集区 | 前者 bubble；后者 count 热力或固定蜂窝，明确“门店密度”并非销量贡献 |
| 只有机场位置，无连接表 | points；不能凭距离自动生成飞线关系 |
| OD 连接只有起终点，没有流量 | `FlyLineViz` 展示连接与方向，不编造流量线宽；若要求比较流量，先确认对应字段 |
| 道路折线但无通行方向，用户只问路网覆盖 | 用 `line` 组件保留真实线形；不从坐标顺序推断通行方向 |
| 设备 ID＋采样时间＋位置，需要按历史时间播放 | 分实体排序、分段后按所选图商能力实现时间轨迹；不能把普通路径线当成历史时钟 |
| 需要“炫酷”呈现区域贡献，同时需准确比较排名 | 平面统计为主，3D 为可切换备选；保持相同聚合值、单位与颜色域 |
