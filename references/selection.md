# 从数据到地图效果的匹配规则

本文件指导 Agent 作出并解释选择；`profile_geo.py` 提供数据证据，不是自动理解业务或自动判定所有 SDK 能力的分类器。不要仅根据文件后缀、点数或出现一个数值列就定图。

## 1. 先形成数据事实

从 profile、必要样例及用户目标提取以下信息。脚本未提供的统计按任务补算，不把未知写成已检测：

| 维度 | 要确认的事实 | 对选型的影响 |
|---|---|---|
| 几何 | 点、路径、区域、多部件；OD 两端；只有地址/行政编码 | 决定可画哪些形状、是否还缺坐标/边界 |
| 记录粒度 | 一行一个门店、订单、车辆采样、区域月份，还是已聚合网格 | 避免重复计数、重复汇总、跨实体连线 |
| 指标 | 数量、金额、强度、比例、等级、正负变化；单位与分母 | 决定面积、连续/发散颜色、求和或加权比率 |
| 时间 | 时间戳/区间、时区、实体内顺序、采样间隔与缺口 | 时间筛选、变化对比和轨迹播放不是一回事 |
| 空间 | CRS 来源、覆盖范围、同位置不同实体、视口中的重叠情况 | 坐标转换、聚合、投影/日期线与拾取 |
| 规模 | 记录数、顶点数、文件字节、更新频率、目标设备 | 原生批量层、WebGL、汇总或切片；通过实测决定 |

## 2. 用数据条件淘汰不成立的效果

| 数据 / 用户问题 | 优先候选 | 前提与淘汰条件 |
|---|---|---|
| 门店销量、订单量、资产规模；比较单体大小 | 数量气泡 + 详情，类别筛选 | 有位置及非负规模；面积对应数值。缺失另画，0 不当缺失；只需位置时等大点 |
| 告警等级、关注点；突出少量事件 | 稳定核心点 + 呼吸/波纹 | 等级阈值有依据；动画为强调，不能暗示实时数据或测得波的传播 |
| 订单/事件记录；哪里集中 | 计数热力、聚合、方格/蜂窝计数 | 确认每行含义；热力表达密集程度，无法替代需要逐个比较的气泡 |
| 每个点带销售额；哪里贡献多 | 加权热力 / 网格求和 | 先验证权重含义和 SDK 支持的数值范围；不得把加权求和替成点数 |
| 设备温度、污染观测；观测强度 | 点色阶，或有依据的网格均值 | 多个观测不能简单相加后当温度；平滑热力不等于经过验证的空间插值 |
| 风险率、转化率、人均值；区域差异 | 区域设色 / 点色阶 | 比率聚合需分子分母；不能将“点多”解释为“风险高” |
| 净增长、亏盈、同比变化 | 发散色阶 + 绝对值气泡 | 保留符号；不能塞进只接受非负权重的热力层 |
| 起终点 + 流量；物流/迁徙关系 | OD 方向线 / 飞线 | 两端可定位且方向明确；缺少中间采样不能冒充真实路线 |
| 实体 ID + 有序位置 + 时间；查看移动过程 | 轨迹回放 / 尾迹 | 实体内排序与分段，处理时间缺口；只有日期列或每行独立订单不能连接 |
| 区域边界 + 区域统计；比较行政区 | 分级设色，可选拉伸 | 按稳定地域编码及边界年份关联；检查未匹配/一对多，只有名称不造边界 |
| 建筑 footprint + 高度，或区域指标柱 | 拉伸 / 棱柱 + 二维备选 | 区分物理高度和指标映射高度，注明单位/比例；3D 遮挡不得妨碍主要比较 |
| 网格/遥感栅格/风矢量 | 专门栅格、等值或矢量方案 | 不强制转点热力。当前分析脚本不直接处理 GeoTIFF/风场，需补专用解析与渲染证据 |

缺少必要输入时给出可执行的替代或仅询问关键缺项。用户点名的效果优先保留，但不能为了“炫酷”编造路径、统计值或业务阈值。

## 3. 将效果落到用户选定平台

先读 [能力索引](capabilities/index.md)，再读所选平台文件。对每个候选逐项判定：

1. **输入成立**：几何、粒度、指标、单位、时间是否满足。
2. **接入可行**：目标 SDK 版本、必需扩展、Key、map ID/安全配置、CRS 与网络是否具备。缺 Key 为待接入，不是厂商不支持。
3. **接口有证据**：公开文档或当前源码能定位类及所需参数；参考 Demo 名称不能当构造器。未确认扩展兼容性标待核实。
4. **交互和性能合适**：是否需要逐条拾取、暂停、筛选、高频更新、倾斜/遮挡；用户设备实际能否承载。
5. **跨平台口径可保持**：颜色、半径、聚合和时间语义一致；不同 native 聚合结果需要明确处理。

只有满足必要条件的候选才按“回答业务问题的程度 → 可读性与交互 → 运行成本 → 用户视觉偏好”排序。选择 1 个主方案和最多 2 个有实质区别的备选；不要用没有依据的精确分数、固定点数阈值或厂商优劣榜。

优先利用适合本任务的公开原生/官方扩展能力。用户只要二维且要求视觉一致时可共用 Canvas；需要飞线遮挡、倾斜、批量 GPU 渲染时按平台选层，不能为了适配方便全部降成屏幕 Canvas。

## 4. 固定映射，再实现切换

- 在源 CRS 或明确的分析 CRS 下计算一次聚合与指标，渲染前再派生目标 CRS 坐标。境内外混合数据不可盲目批量加偏移。
- 气泡固定全量的面积域；颜色固定类别/阈值；筛选与切图不自动重标色。绘图大小区分半径/直径以及 px/meter。
- 严格比较网格时固定网格定义、大小、原点、CRS、成员和聚合函数，输出共同面数据。屏幕聚合仅用于浏览，可以随 zoom 改变成员，但不要称作稳定统计区域。
- 原生热力的核函数、带宽、归一化、累加和颜色曲线不同。同一批点、同一个最大值，并不能证明热力数值逐像素等价。要求严格比较时统一生成密度场或改用共同统计网格。
- 3D/动画增强可因平台不同而变化，但保留同一业务指标、筛选与详情；没有对应层时显示实际降级效果及原因。

## 5. 保留一份简短可检查的选型结果

生成代码前把方案保存在任务工作目录的 `viz-plan.json` 或等价说明中，不保存 Key。以下为结构示意，数值和路线由实际分析填写，不是脚本自动产生的结果：

```json
{
  "intent": "比较门店订单规模，并突出高等级告警",
  "data": {"geometry": "Point", "grain": "store", "sourceCrs": "wgs84"},
  "metric": {"field": "orders", "unit": "单", "aggregation": "none", "missing": "separate"},
  "primary": {"effect": "bubble", "reason": "比较单店数量，需要逐点查看"},
  "secondary": [{"effect": "pulse", "reason": "仅对有明确告警等级的点强调"}],
  "encoding": {"size": "area", "domain": "full-dataset-fixed", "color": "category"},
  "routes": [
    {"provider": "maptec", "api": "GeoJSONOverlay.circleStyle", "basis": "source-verified", "status": "pending-runtime"},
    {"provider": "amap", "api": "Loca.PointLayer", "basis": "official-doc", "status": "pending-runtime"}
  ],
  "comparison": {"level": "same-business-metric", "fallback": "2d-bubble"},
  "rejected": [{"effect": "heatmap", "reason": "会混合相邻门店，不能作为单店比较的主图"}]
}
```

需要写出所选 SDK/扩展实际版本、映射域数值、证据链接、额外依赖和仍缺的配置；示意字符串不应原样留在最终方案。可运行代码与真实底图验收完成前，不能把 `pending-runtime` 改成通过。

## 选型校验案例

这些是可供人工复核的行为案例，不代表自动分类测试已实现：

| 请求 / 数据 | 应产生的判断 |
|---|---|
| 上传门店订单 CSV，选择 Maptec + 高德，要求气泡与呼吸 | 分析零值/缺失/重叠；气泡走 GeoJSONOverlay 与 Loca.PointLayer；呼吸走 CircleOverlay 组合与 Loca.ScatterLayer；固定面积域 |
| 选择 Google，要展示订单集中区 | 核实每行订单计数；用受支持的第三方 HeatmapLayer 或自行实现；禁止生成旧 google.maps.visualization.HeatmapLayer |
| 腾讯上显示传感器温度，有负值和小数 | 不截负、不取整、不把温度写进仅声明正整数 count 的 Heat；优先 Dot 颜色或预计算平均值区域 |
| 百度 4.0 + 炫酷飞线，只给起终点 | 定义 OD；核查 MapVGL 与当前 4.0 实例兼容，FlyLineLayer 的额外包；未核实前保留二维方向线备选 |
| Mapbox + 腾讯，对比六边形销售总额 | 共同生成格网并求和，再用面层；不能 Mapbox 求和、腾讯原生 Hexagon 默认点数 |
| 日期 + 门店点，但每店只有一条记录 | 可按日期筛选；不形成车辆轨迹，不因为有 time 列就选 Trips/Trail |
| 行政区转化率，只有百分比没有分母 | 可显示已有区域比率，不能跨区简单平均；若需上卷汇总先索取分子分母 |
| Maptec SDK 实例缺少 PulseLinkOverlay | 标明当前版本缺能力，按二维 OD 组合实现或使用用户确认的兼容版本；不伪造类、不悄悄改用其他厂商 |
