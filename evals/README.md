# Skill 行为评估

`cases.json` 是有明确用户问题、原始附件和评判条件的评估集，fixtures 为合成数据，不能对外当作真实城市统计。运行结果写到仓库外或被忽略的 work/，不存 Token。

## 自动冒烟

```bash
python3 evals/run_smoke.py --out work/eval-smoke
```

检查实际 profiler 候选和打包结果，使用案例中的显式测试 spec 生成 HTML；这是确定性处理/打包验证，不是 AI 自动选型或真实底图验收。当前 smoke 不使用 Key，不产生地图服务调用。

## Agent 端到端

在目标应用的新对话中只提供案例 prompt、对应原始 fixture 和 Skill；不要把 expected/spec 作为用户输入。由 Agent 独立分析、选图和实现。用户明确选择 Mapbox 时才提供获授权的浏览器 Token 配置。不要为了测试扫描历史密钥。

逐案例记录应用/版本、模型、Skill commit、实际产物路径和以下结果：

- 分析正确：字段、粒度、缺失、坐标与分母处理符合数据。
- 选型正确：主图回答用户问题；不存在 expected 中明确禁止的误解。允许不同但有依据的实现和布局。
- 完整交付：生成 HTML 与所需资源，启动命令可复现，无再次上传的强制工作台。
- 渲染归属：逐层核对原生/官方扩展优先；图商确有能力缺口时允许第三方/自绘，检查缺口依据、来源标注及地图适配。无依据跳过原生能力、补充层冒充原生或切图商未重新判断能力记 fail。
- 接入与交互：真实底图及位置可见，图例与数值吻合、拾取和筛选有效。只在用户要求时检查多图商 A→B→A。
- 缺项处理：只问会影响结果的缺项；未提供 Key 时清楚标注 pending-key，无浏览器工具时标注视觉未验收。

每项记录 pass/fail/pending 和证据，不将 pending 计为成功；补充完成耗时、澄清次数和具体失败原因。先在 Codex 运行，再在 Claude Code、WorkBuddy 复跑同组任务。安装/单元测试通过不能自动填入跨应用通过记录。
